# MemGarden

> 🇬🇧 [English](../introduction.md) · [저장소](https://github.com/ohora23/memgarden)

AI 코딩 어시스턴트는 매 세션을 기억상실 상태로 시작한다. 같은 파일을 다시
읽고, 같은 결론을 다시 도출하고, 지난주에 정한 것을 다시 묻는다. MemGarden은
그걸 멈추는 계층이다: 대화를 자동으로 포착하고, 로컬 LLM으로 사실을 뽑아내고,
서로 연결한 뒤, 방금 입력한 프롬프트에 필요한 몇 개의 기억만 **밀리초 한 자릿수**
안에 돌려준다.

원래는 Python 데몬 + 임베디드 Postgres로 돌던 개인용 장기기억 시스템이었고,
이건 그것을 **Rust로 처음부터 다시 지은 것**이다. 전부 한 머신에서, 두 개의
프로세스로, 하나의 파일 위에서 돈다.

## 무엇을 하는가

- 모든 Claude Code 세션을 **자동 포착**한다. 훅 4종이 한 턴에 1밀리초도 쓰지
  않는다.
- 자기 Ollama 모델로 사실을 **추출**하고, 엔티티와 관계의 그래프로 연결한다.
- FTS5 BM25와 벡터 KNN을 역순위 융합(RRF)으로 합쳐 토큰 예산 안에서 **회수**하고,
  질문이 시간적이면 시간으로 거른다.
- 백그라운드에서 **통합(consolidation)** 한다 — 중복은 거부가 아니라 병합,
  관찰은 지식으로 접붙임.
- 매 retain마다 입력 캡이 절약한 양을 이득 원장에 적어 **자기 자신을 측정**한다.

프로젝트별 뱅크가 한 저장소의 기억을 다른 저장소로부터 분리한다. 아무것도 이
머신을 떠나지 않는다.

## 무엇이 다른가

- **바이너리 하나, 파일 하나, 외부 프로세스 0.** sqlite-vec와 FTS5를 얹은
  SQLite가 벡터·키워드·그래프를 인프로세스로 처리한다. 띄울 DB 서버가 없고,
  데이터를 잃을 재시작 경합이 없고, 백업은 `cp memgarden.db`다.
- **안 보일 만큼 빠르다.** 회수는 예산보다 한 자릿수 안쪽에서 끝나고, 훅 계층
  전체가 10ms 허용치에 대해 한 턴당 1ms 미만이다.
- **정책이 아니라 구조로 로컬이다.** 추출은 당신의 Ollama를 쓰고, 임베딩과
  리랭커는 바이너리에 내장돼 CPU로 강제된다 — LLM과 VRAM을 두고 싸우지
  않는다. 실수로 켤 클라우드 경로 자체가 없다.
- **한국어가 제대로 된다.** CJK는 단어 경계가 없어서 순진한 전문 색인은 조용히
  아무것도 못 찾는다. FTS 계층은 그걸 전제로 만들어졌고, 가드 테스트가 회귀를
  빌드 실패로 잡는다.
- **신뢰할 수 없는 입력이 닿는 모든 곳에 상한이 있다.** 이 시스템의 모든 캡은
  이전 시스템에서 그게 없어서 실제 사고가 났기 때문에 존재한다.
- **회수 품질은 주장이 아니라 측정이다.** 고정된 코퍼스와 등급이 매겨진 골드
  질의가 recall@k / MRR / nDCG를 산출한다. 그래서 랭킹 변경은 느낌이 아니라
  델타를 보고한다 — 이미 "당연히 맞아 보이던" 결정 하나를 뒤집었다.
- **스위치가 스스로 넘어가지 않는다.** 훅 설치는 *shadow* 모드로 연결한다:
  실제 호출, 실제 지연, 실제 적재 — 그리고 두 번째 별도 단계를 밟기 전까지
  모델은 아무것도 보지 않는다.

## 현황

Phase A·B·C(기반, 코어 파이프라인, 훅)는 머지됐거나 코드 완료다. 마이그레이션,
웹 UI, 전환 자체가 남았다. 구시스템은 아직 돌고 있고, 세 개의 인수 게이트 —
품질 동등성, 성능, 무손실 이전 — 이 모두 충족될 때까지 계속 돈다.

[로드맵](roadmap.md)에 상세가 있다. 지금 라이브 전환을 막고 있는 미결 결함
포함.
