# 로드맵

> 🇬🇧 [English](../roadmap.md)

재구축이 어디까지 왔는지, 무엇이 남았는지, 그리고 이것이 베끼고 있는 시스템을

## 전환 게이트

셋 **모두** 충족될 때 구시스템을 내린다. 그 전에는 아니다.

### AC-1 — 품질 동등성 — *지금 수집 가능, 아직 미수집*

고정 질의 세트(기존 A/B 로그 8건 + 신규 12건)에서 회수 품질이 현행 시스템 이상
이어야 하며, 판정은 사용자가 한다.

계측기는 이미 있다: 레거시 훅과 나란히 `shadow` 모드로 설치하면 매 프롬프트마다
MemGarden이 *주입했을* 내용이 `shadow-recall.jsonl`에 쌓이고, 같은 실제 세션에서
뱅크도 함께 찬다. 그 로그와 등급 골드 세트가 근거다.

### AC-2 — 성능 — ✅ **충족**

| | 요구 | 실측 |
|---|---|---|
| 회수 p50 | ≤ 35ms | ✅ |
| 회수 p95 | ≤ 60ms | ✅ |
| **훅 오버헤드** | **< 10ms** | **턴당 0.845ms** |
| 적재 캡 절감 | −55…−87% 유지 | ✅ |

훅 수치는 한 턴의 `recall` + `retain`이고, 같은 바이너리가 아무것도 안 하는 arm과
인터리브 페어링해 잰 값이다. 참고로 레거시 Python 훅은 **비활성 경로에서도 33ms**
— 이것들이 일하는 비용보다 아무것도 안 하는 비용이 더 크다.

### AC-3 — 무손실 이전 — 🔄 **이전은 돌아간다. 그것을 증명할 계측기가 아직 없다**

기존 뱅크의 노드·링크·문서 수가 일치해야 하고 50건 무작위 내용 대조도 통과해야
한다.

Phase D의 세 PR 중 둘이 실동작 부분을 올렸다. `mg-migrate snapshot`은 읽기 전용
GET만으로 레거시를 동결하고 15개 무결성 속성 중 하나라도 깨지면 거부한다.
`mg-migrate import`는 그 아카이브를 SQLite로 옮긴다. 레거시 자신의 동결된 `/stats`
대비 **4개 뱅크** 실측: 문서 25 == 25, **노드 5,288 == 5,288**, 저작된 인과 링크
200 == 200, 관측 1,747건과 그 출처 엣지 2,114개.

**이것은 AC-3 충족이 아니다.** AC-3은 *검증* 기준이고, MG-2 — 3단계 대조와 50건
내용 diff — 는 아직 작성되지 않았다. 행을 쓴 바로 그 프로그램이 찍은 숫자는 그 행이
옳다는 증거가 아니며, 검증기를 별도 오라클을 가진 별도 PR로 둔 이유가 정확히
그것이다. Phase F는 MG-2의 리포트에서 AC-3을 읽거나, 읽지 않는다.

이전이 확립한 것 중 Phase F가 필요로 할 두 가지:

* **모든 숫자가 같아질 수는 없고, 정직한 쪽이 그렇다고 말한다.** 저작된 `caused_by`
  엣지는 정확히 이관된다. `temporal`과 `semantic`은 *재구축*된다 — 의미 엣지는
  우리 것이지 레거시 것이 아닌 임베딩 공간의 함수이고, 레거시의 시간 이웃 질의는
  우리가 적용하는 24시간 창을 적용하지 않기 때문이다. `entity` 링크는 양쪽 어느
  저장소에도 존재하지 않는다;
* **이전은 비용 0으로 리허설된다.** `--db <scratch>`는 두 데몬을 건드리지 않은 채
  살아 있는 DB 옆에 완전한 이전본을 만든다. 위 숫자가 그렇게 측정됐다.

나머지 넷(AC-4 그래프 뷰어, AC-5 대시보드, AC-6 지표, AC-7 PR 규율)은 추적되지만
종료를 막지는 않는다.

## 알려진 한계와 미결 결함

무엇이 무엇을 막는지 순서대로.

### ~~커서 간극~~ — 해결됨 (HK-1g)

청크 하나가 실패한 채 `done`으로 끝난 적재 작업이 열던 간극을, 워커의 무조건 확정이
`MAX` 병합으로 지워 버리던 결함. 아래에 예측된 형태 그대로 수정됐다 — 요청에
`offset_from`, 작업 행에 영속화, 그리고 범위 가드가 걸린 세 번째 갱신 채널.
`docs/design/hk-1g-retain-cursor-gap.md`.

아래 원문은 기록으로 남긴다. 하면 안 되는 형태가 적혀 있는 곳이기 때문이다.

### 원래 항목

청크 하나가 실패한 채 `done`으로 끝난 적재 작업이 낙관적 커서와 내구 커서 사이에
간극을 열고, 워커의 무조건 확정이 `MAX` 병합으로 그 증거를 지운다. shadow 실행이
만드는 GPU 경합 — 한 카드 위의 추출 파이프라인 둘 — 아래에서 청크 실패는 바로 그
확률이 올라가는 사건이다.

수정의 형태는 알려져 있고(적재 요청에 `offset_from` → 작업 행에 저장 → 가드된 세
번째 갱신 채널), **하지 말아야 할 형태**도 알려져 있다: `confirm_if_settled`는
요청 경로가 이미 낙관적 커서를 써놨기 때문에 모든 세션의 내구 커서를 영원히 0에
묶어버린다.

그때까지 `hooks status`는 `unconfirmed` 바이트를 **하한**으로 보고한다 — 0이 아닌
값은 실재이고, 0은 수렴의 증거가 아니다.

### 더 작은 것들, 재진입 기준과 함께

| 한계 | 무엇이 바꾸는가 |
|---|---|
| 리랭커 기본 **꺼짐** | +14ms p50을 흡수할 호출자, 또는 적재 루프를 제공 부하의 90% 아래로 굶기지 않는 리랭크 경로 |
| 세션당 in-flight 적재 작업 1개 | 적재가 매 턴 발동하거나, 작업 시간이 상시 10턴을 넘길 때 |
| `SubagentStop` 적재 없음 | 사이드체인 항목이 있는 트랜스크립트 **그리고** 그로 인한 측정된 회수 개선 |
| 제거는 접두사 매칭이지 출처 추적이 아님 | 실제로 손으로 추가한 훅을 잃는 사례가 생겼을 때 |
| Linux 전용 | Windows 사용자 |

`docs/parity-gaps.md`가 일부러 이식하지 않은 레거시 동작의 전체 목록이며, 각 행에
그것을 다시 열 사실이 적혀 있다.

## v1 이후

v1 범위 밖. 의도가 아니라 이유를 기록해 둔다:

- **Obsidian vault 내보내기** — 기억 노드를 백링크가 달린 마크다운으로, 기존
  Library vault에 합류. 그래프 뷰어의 대체가 아니라 동반자.
- 이식한 dedup + 관찰 라운드를 넘어서는 **통합 고도화**.
- **LLM 저지 기반 적중률 지표**(측정 프레임워크의 Layer 3). Layer 1·2는 결정적이고
  비용이 0이다. Layer 3은 저지가 필요하고, 저지는 자기 평가가 필요하다.
- **멀티유저·원격 배포·클라우드 LLM·모바일.** 연기가 아니라 **제외**다. 실수로
  켤 클라우드 경로가 없다는 건 지킬 값어치가 있는 성질이다.
