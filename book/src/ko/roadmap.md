# 로드맵

> 🇬🇧 [English](../roadmap.md)

재구축이 어디까지 왔는지, 무엇이 남았는지, 그리고 이것이 베끼고 있는 시스템을
대체해도 되는 시점을 결정하는 구체적 사실들.

## 단계

| 단계 | 범위 | 상태 |
|---|---|---|
| **A — 기반** | 워크스페이스 + CI, SQLite 스키마(vec + FTS5 + 그래프 + temporal), REST 골격, 지표 배관 | ✅ 머지됨 |
| **B — 코어 파이프라인** | 임베딩 · Ollama 추출 · retain 적재 · 하이브리드 회수 · 엔티티/그래프 · temporal · 통합 · reflect · 리랭커, 벡터공간 태깅과 회수품질 하네스 포함 | ✅ 머지됨 |
| **C — 훅** | 세션/턴 상태 · CLI 기반 + 지연 하네스 · session-start · recall · 트랜스크립트 델타 리더 · retain · 전환 스위치 | ✅ 코드 완료 |
| **D — 마이그레이션** | 읽기 전용 레거시 스냅샷(MG-1a) ✅ · 아카이브 → SQLite 임포터(MG-1b) ✅ · AC-3 검증기(MG-2) ✅ | ✅ 코드 완료 |
| **E — UI·지표** | 대시보드, 그래프 API, WebGL 뷰어(팬/줌/드래그, 실시간 SSE), 원장 뷰, 뱅크 조감 | ✅ 머지됨 |
| **F — 전환** | AC-1~3 게이트 실행 → 구시스템 종료 → 레거시 레포에 최종 기록 | ⏳ AC-1 실행 완료, 사용자 서명 대기 |

의존성은 `A → B → (C, D, E 병렬) → F`. 그래프 뷰어는 Phase B의 링크 데이터만
필요하고 C나 D는 필요 없다.

## 전환 게이트

셋 **모두** 충족될 때 구시스템을 내린다. 그 전에는 아니다.

### AC-1 — 품질 동등성 — *실행 완료, 사용자 서명 대기*

고정 질의 세트(기존 A/B 로그 8건 + 신규 12건)에서 회수 품질이 현행 시스템 이상
이어야 하며, 판정은 사용자가 한다.

2026-08-12에 두 라이브 시스템에 같은 손잡이로 20개 질의를 보냈다. 판정 기준은
**첫 질의를 보내기 전에** 커밋했다(`docs/evidence/ac-1-criteria.md`).

| | |
|---|---|
| 우세 | **6** |
| 동등 | 2 |
| 열세 | **5** |
| 판정 불가(양쪽 다 0히트) | 7 |

**게이트 조건(`열세 ≤ 우세`)은 6 대 5로 성립한다** — 판정 가능한 13건에서 한 건
차이로. 같은 세트의 지연은 p50 **11.5 ms**, 레거시 **51.0 ms**. 전체 결과와 열세
5건의 인용은 `docs/evidence/ac-1-memcompare.md`.

PRD가 이 판정을 사용자에게 맡기므로 여기 적힌 것은 권고와 그 근거이고, 사용자가
서명하기 전까지 게이트는 충족이 아니다.

이번 실행에서 남는 것 세 가지:

* **shadow 프롬프트는 질의 세트가 아니다.** 실제 프롬프트 6개 중 5개가 단독으로
  재생하면 판정 불가였다 — "이게 맞나?"는 주변 대화 없이는 지시 대상이 없다.
  계측기는 작동한다; 살아 있는 세션에서 떼어낸 프롬프트가 먹일 대상으로 틀렸다.
* **결론형 질문은 어느 코퍼스에도 답이 없다.** 그 답은 큐레이션된 `MEMORY.md`에
  있고 두 시스템 모두 그것을 캡처하지 않는다. AC-1에 두 번째 코퍼스를 붙이거나,
  자동 캡처 회수로 범위를 명시적으로 한정해야 한다 — 미결 결정,
  `docs/evidence/ac-1-shadow.md`에 기록.
* **열세 5건에 대해 제시한 진단은 측정을 통과하지 못했다.** 아래 랭킹 시도 참조.

### AC-2 — 성능 — ✅ **충족**

| | 요구 | 실측 |
|---|---|---|
| 회수 p50 | ≤ 35ms | ✅ |
| 회수 p95 | ≤ 60ms | ✅ |
| **훅 오버헤드** | **< 10ms** | **턴당 0.845ms** |
| 적재 캡 절감 | −55…−87% 유지 | ✅ |

훅 수치는 한 턴의 `recall` + `retain`이고, 같은 바이너리가 아무것도 안 하는 arm과
인터리브 페어링해 잰 값이다. 참고로 레거시 Python 훅은 **비활성 경로에서도 33ms**
— 이것들이 일하는 비용보다 아무것도 안 하는 비용이 더 크다.

### AC-3 — 무손실 이전 — ✅ **리허설에서 계측기가 충족을 선언했다**

기존 뱅크의 노드·링크·문서 수가 일치해야 하고 50건 무작위 내용 대조도 통과해야
한다.

Phase D의 세 PR 중 둘이 실동작 부분을 올렸다. `mg-migrate snapshot`은 읽기 전용
GET만으로 레거시를 동결하고 15개 무결성 속성 중 하나라도 깨지면 거부한다.
`mg-migrate import`는 그 아카이브를 SQLite로 옮긴다. 레거시 자신의 동결된 `/stats`
대비 **4개 뱅크** 실측: 문서 25 == 25, **노드 5,288 == 5,288**, 저작된 인과 링크
200 == 200, 관측 1,747건과 그 출처 엣지 2,114개.

**그리고 이제 MG-2가 그렇게 말한다 — 그것이 핵심이다.** `mg-migrate verify`는 세
오라클(레거시의 동결된 `/stats`, 동결된 아카이브, 데이터베이스)을 읽고 4뱅크
리허설에서 **exit 0**을 낸다: Tier-1 등가 전부 통과(문서 25, 노드 5,288, 저작된
인과 엣지 200, 출처 엣지 2,114, 엔티티 3,917, 멘션 10,379), temporal 자기 일관성
105,016에서 양방향 불일치 0, 그리고 **50건 내용 대조에서 차이 0**.

Phase F는 커밋 임포트에 대해 이를 재실행하며, 그것이 결정하는 실행이다. 행을 쓴
바로 그 프로그램이 찍은 숫자는 그 행이 옳다는 증거가 아니고, 검증기를 별도 오라클을
가진 별도 프로그램으로 둔 이유가 정확히 그것이다.

이전이 확립한 것 중 Phase F가 필요로 할 두 가지:

* **모든 숫자가 같아질 수는 없고, 정직한 쪽이 그렇다고 말한다.** 저작된 `caused_by`
  엣지는 정확히 이관된다. `temporal`과 `semantic`은 *재구축*된다 — 의미 엣지는
  우리 것이지 레거시 것이 아닌 임베딩 공간의 함수이고, 레거시의 시간 이웃 질의는
  우리가 적용하는 24시간 창을 적용하지 않기 때문이다. `entity` 링크는 양쪽 어느
  저장소에도 존재하지 않는다;
* **이전은 비용 0으로 리허설된다.** `--db <scratch>`는 두 데몬을 건드리지 않은 채
  살아 있는 DB 옆에 완전한 이전본을 만든다. 위 숫자가 그렇게 측정됐다.

나머지 넷(AC-4 그래프 뷰어, AC-5 대시보드, AC-6 지표, AC-7 PR 규율)은 추적되지만
종료를 막지는 않는다. **AC-4의 렌더링 벤치마크는 2026-08-19에 실측했고 충족한다**:
최대 라이브 뱅크의 3,200노드·57,890엣지가 팬+줌에서 **p50 3.6ms / p95 5.3ms**로
그려진다 — 60fps 예산 대비 3.2배 여유 — 호버 히트테스트는 p95 0.40ms. 같은 측정이
진짜 천장도 짚는다. 렌더러가 아니다: d3-force가 메인 스레드에서 그 크기에 **틱당
13ms**, 안정까지 6.1초 걸린다.
[숫자와 단서](../../docs/evidence/ac-4-render.md).

임포트해서 재면 **열여섯 자리까지** 나오는 값이다. 8번 줄은 *희소 그래프* 시절
숫자로, CE-7 수정이 코퍼스의 시맨틱 엣지를 681개에서 43,830개로 늘리면서 밀려났다
— 하락 자체는 `README.md`에 표로, 이유는 `docs/design/mg-1-migration.md`에 이미
적혀 있다. 철회하기 전에 결정성도 측정했다: 동결 코퍼스를 두 번 임포트하면 노드·
링크·엔티티·벡터가 모두 해시까지 동일하다.

**실제로 빠져 있던 것:** 실행이 원장을 읽지 않았다. 비교가 몇 달 전 문서에 옮겨
적힌 숫자를 상대로 사람 머릿속에서 일어났고, 그래서 정당하게 밀려난 baseline이
표류처럼 읽혔다. 이제 `recall_bench bench`는 코퍼스 다이제스트와 `rerank_top_k`가
일치하는 최신 원장 줄과 그 차이를, 차이가 없으면 `reproduces line N to the digit`을
함께 찍는다. 아무것도 기록하지 않는 실행에서도 읽는데, 바로 그때가 낡은 문서
말고는 비교 대상이 없는 경우이기 때문이다.

### AC-1의 열세를 고치려던 랭킹 수정은 측정했고 넣지 않았다 — 2026-08-12

memcompare 기록은 열세 5건 중 4건이 행위 기록("X를 실행했다")이 내용을 밀어낸
탓이라고 제안했다. 후보 두 개를 만들어 측정했고 **둘 다 넣지 않았다.** 진단은
근거 없는 가설로 강등한다. 전체 숫자는 `docs/evidence/ac-1-ranking-attempt.md`.

* **recency 창 좁히기**(365일 → 30/7/3일)는 MRR을 최대 +0.133 올리고 recall@5를
  0.218 → 0.192로 깎는다 — CE-11 리랭커를 꺼둔 바로 그 거래다. 가장 좋은 창이
  골드 코퍼스 자체의 기간과 일치하는데, 이는 수정이 아니라 코퍼스에 맞춘 것이다.
* **행위 기록 감점**은 눈으로 본 정밀도가 20/20인데 벤치마크는 **0.0(완전 삭제)을
  포함한 모든 강도에서** +0.003~0.006만 움직인다 — 잡음이다. 게다가 골드가
  *관련 있음*으로 라벨한 276개 노드 중 5개에 걸리고, 그중 하나가 AC-1 판정에서
  잡음이라고 불린 `doctor --dry-run` 기록이다. 라벨한 쪽과 판정한 쪽의 의견이
  갈리는데, 판정한 쪽은 시스템을 만든 당사자이기도 하다.

이 실행이 실제로 규명한 것: 문제는 점수의 분포다. 가장 크게 진 질의에서 12개
항목이 서로 **0.042** 안에 모두 들어가고, recency는 전 항목 0.97(2주짜리 뱅크에
365일 감쇠), proof는 중립이다. 결국 시맨틱 유사도 하나가 순서를 정하는데, 그것이
행위 기록에 0.750, 진짜 관련 항목에 0.752를 준다.

### 커밋 후 `resolve_fact`는 마이그레이션된 뱅크 전체를 상대로 돈다 — CE-7, MG-1b가 규명했으나 고치지는 않은 것

MG-1b는 조밀한 후보 집합에서 `entities::resolve_fact`의 퍼지 패스가 무엇을
하는지 실측했다: **3,917개 이름 중 77개가 다른 엔티티로 녹아 없어졌고, 그중
33개는 유사성이라 할 만한 것이 없었다** — `ce-4`→`ce-1`, `ci.yml`→`cli.mjs`,
`shell`→`schedule`. 그래서 *임포터*에서 그 패스를 제거했다. 임포트는 레거시가
이미 정규화를 마친 대상에 대한 일회성 벌크 작업이기 때문이다.

retain에서는 제거하지 않았고, 할 수도 없다 — 리졸버가 쓰이라고 만들어진 경로가
그쪽이다. 다만 두 사실 때문에 커밋 후 같은 조건이 재현된다:

* `load_resolution_context`는 `WHERE bank_id = ?1 ORDER BY last_seen DESC
  LIMIT 5000`(`graph.rs:54-72`) — 청크별이 아니라 **뱅크 전체**다. 마이그레이션된
  `bank-b`은 2,491개 엔티티로 상한 아래이므로, 매 retain이 모든
  멘션을 그 전부와 대조한다;
* `resolution_score`는 `ratio*0.5 + overlap*0.3 + temporal*0.2`
  (`entities.rs:160-176`)이라, 같은 날 공동출현한 쌍은 이름을 비교하기 전에 이미
  0.6 게이트의 0.5를 쥔다.

마이그레이션된 뱅크에만 해당하는 2차 효과도 있다. `resolve_fact`는 **정확 일치
단축 경로 없이** argmax를 취하는데, 마이그레이션된 엔티티의 `last_seen`은 *레거시*
날짜다. 커밋 몇 달 뒤면 정확히 일치하는 마이그레이션 후보가 쥐는 값은
`1.0*0.5 + overlap*0.3 + 0`이고, 더 최근에 공동출현한 근사 후보가 이를 앞지를 수
있다 — 나중의 `CE-4`가 마이그레이션된 `ce-4` 행이 아니라 `ce-1`으로 갈 수 있다.

**수정의 형태:** `resolve_fact` 한 줄 — `canonical_name` 정확 일치는 정의상 최선의
일치이므로 argmax를 단축할 수 있다. **무엇이 그것을 정당화하는가:** 회수 영향을
보여 주는 AX-2 실행. MG-1b가 지나가는 길에 이를 바꾸지 않은 것과 같은 이유다.
마이그레이션은 아무도 측정하지 않는 사이에 CE-7을 재단할 권한이 없다.

### 테스트 스위트가 동시 부하에서 메모리를 손상시킨다 — 마이그레이션이 아니라 `memgarden-store`

`cargo test --workspace`가 `memgardend` 테스트 바이너리에서 간헐적으로 SIGSEGV
또는 abort로 죽는다. 동일 하네스 실측: **`bccaed9`(Phase D 임포터 테스트 이전)
8회 중 0회, `9fd1930` 8회 중 2회.** 8개 프로세스 × 32스레드 합성 부하에서
임포터 테스트는 **32개 프로세스 중 13개**가 죽는다.

서로 다른 백트레이스 3종이 전부 **SQLite 내부의 힙 손상**이다. FTS5 인덱스
머지가 낡은 버퍼 포인터로 varint를 쓰는 지점(`fts5IndexMergeLevel` →
`sqlite3Fts5PutVarint`), `0xec9117eb9cd4eabf`에서의 FTS5 varint 읽기, 그리고
할당자 자신(`pcache1Alloc` 아래 `sqlite3MemSize(pPrior=0x1008)`). SQLite는
`THREADSAFE=1`, `MUTEX_PTHREADS`, 3.53.2다.

**마이그레이션 코드가 아니며, 그것을 말해 주는 것은 재현자다.**
`memgarden-store` 안의 25줄 — 파일 기반 `Db`를 열고, 긴 텍스트 노드 150개를
`nodes::insert_batch`하고, 드롭 — `migrate` 관여 없이, 링크도 재오픈도 없이
같은 부하에서 **32개 중 6개**가 죽는다. Phase D의 테스트는 그저 실질적인 FTS5
콘텐츠를 가진 파일 기반 DB 수십 개를 동시에 여는 최초의 스위트였을 뿐이다.

배제한 것(모두 논증이 아니라 실측): 스레드 스택 크기(`RUST_MIN_STACK=32M`
무변화), `mmap_size`(0으로 해도 무변화), `sqlite-vec`(`vec_nodes` 삽입 제거해도
무변화), 풀 생성 직렬화(무변화). 원인이 아닌 기여 요인: 커넥션**당**
`cache_size` 64 MiB와 `mmap_size` 256 MiB가 살아 있는 풀 수만큼 곱해진다 —
캐시를 2 MiB로 줄이면 13/32가 9/32로 내려간다.

**데몬의 형태는 연루되지 않는다.** 파일 기반 DB 1개, 16스레드, FTS5를 동반한
삽입 6,400건: 10회 실행 0회 실패. 짧게 사는 DB 30개에 각 250건 삽입, 64스레드:
20회 실행 0회 실패. 동시 DB 다수 *와* 실질적인 FTS5 인덱스 구축이 함께 있어야
한다.

**지금의 비용:** 부하 상태에서 `cargo test --workspace`를 게이트로 신뢰할 수
없으므로, 이 결함이 닫히기 전까지 PR의 테스트 집계는 그 단서를 달고 읽어야
한다. **무엇이 닫는가:** ASAN 빌드. 이 레포가 고정하지 않은 nightly 툴체인이
필요하며, 위 최소 재현자가 그 입력이다.

### ~~커서 간극~~ — 해결됨 (HK-1g)

청크 하나가 실패한 채 `done`으로 끝난 적재 작업이 열던 간극을, 워커의 무조건 확정이
`MAX` 병합으로 지워 버리던 결함. 아래에 예측된 형태 그대로 수정됐다 — 요청에
`offset_from`, 작업 행에 영속화, 그리고 범위 가드가 걸린 세 번째 갱신 채널.
`docs/design/hk-1g-retain-cursor-gap.md`.

아래 원문은 기록으로 남긴다. 하면 안 되는 형태가 적혀 있는 곳이기 때문이다.

### 원래 항목

청크 하나가 실패한 채 `done`으로 끝난 적재 작업이 낙관적 커서와 내구 커서 사이에
간극을 열고, 워커의 무조건 확정이 `MAX` 병합으로 그 증거를 지운다. shadow 실행이
만드는 GPU 경합 — 한 카드 위의 추출 파이프라인 둘 — 아래에서 청크 실패는 바로 그
확률이 올라가는 사건이다.

수정의 형태는 알려져 있고(적재 요청에 `offset_from` → 작업 행에 저장 → 가드된 세
번째 갱신 채널), **하지 말아야 할 형태**도 알려져 있다: `confirm_if_settled`는
요청 경로가 이미 낙관적 커서를 써놨기 때문에 모든 세션의 내구 커서를 영원히 0에
묶어버린다.

그때까지 `hooks status`는 `unconfirmed` 바이트를 **하한**으로 보고한다 — 0이 아닌
값은 실재이고, 0은 수렴의 증거가 아니다.

### 더 작은 것들, 재진입 기준과 함께

| 한계 | 무엇이 바꾸는가 |
|---|---|
| 리랭커 기본 **꺼짐** | +14ms p50을 흡수할 호출자, 또는 적재 루프를 제공 부하의 90% 아래로 굶기지 않는 리랭크 경로 |
| 세션당 in-flight 적재 작업 1개 | 적재가 매 턴 발동하거나, 작업 시간이 상시 10턴을 넘길 때 |

| 제거는 접두사 매칭이지 출처 추적이 아님 | 실제로 손으로 추가한 훅을 잃는 사례가 생겼을 때 |
| Linux 전용 | Windows 사용자 |

`docs/parity-gaps.md`가 일부러 이식하지 않은 레거시 동작의 전체 목록이며, 각 행에

## v1 이후

v1 범위 밖. 의도가 아니라 이유를 기록해 둔다:

- **Obsidian vault 내보내기** — 기억 노드를 백링크가 달린 마크다운으로, 기존
  Library vault에 합류. 그래프 뷰어의 대체가 아니라 동반자.
- 이식한 dedup + 관찰 라운드를 넘어서는 **통합 고도화**.
- **LLM 저지 기반 적중률 지표**(측정 프레임워크의 Layer 3). Layer 1·2는 결정적이고
  비용이 0이다. Layer 3은 저지가 필요하고, 저지는 자기 평가가 필요하다.
- **멀티유저·원격 배포·클라우드 LLM·모바일.** 연기가 아니라 **제외**다. 실수로
  켤 클라우드 경로가 없다는 건 지킬 값어치가 있는 성질이다.
